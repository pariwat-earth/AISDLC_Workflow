# Stage 4 — UI mockup

## Who
The human works in a design tool of their choice (for example Claude Design) with the Client. UI Designer (AI) supports and checks.

## How
The result is **the main screens the Client has accepted**, which set the theme for the whole system.

- 4a. The human takes `SA/SA_design.md` into the design tool. On request, the AI writes a UI spec per screen (layout, fields, actions) as text ready to paste.
- 4b. The human adjusts with the Client until the main screens are accepted.
- 4c. The human exports the result (screenshots or HTML) into `UI_Mockup/` and gives the path.
- 4d. The AI reads the mockup and reports whether it matches the SA document. Where the Client changed something, fix the SA document (CLAUDE.md section 4.1). PM cross-checks that every screen has an API behind it in `SA/tasks.md`.

**Screens and parts not in the mockup**, including ones added or removed later, are built in the same theme: the same colours, type, spacing, and components as the main screens. They do not need a new mockup.

**Fully automatic option**: the human says "skip 4a–4c, write the mockup yourself as HTML or components of the tech stack." Faster and uninterrupted; less polished than a design tool. The human still approves the result.

## Output
Files in `UI_Mockup/`

## Done when
The accepted main screens are in `UI_Mockup/` · the SA document matches the mockup · every screen has an API behind it.

## Human approves
The main screens (with the Client's acceptance, when there is a Client) and any SA changes that came from them.
