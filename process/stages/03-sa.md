# Stage 3 — System design and task breakdown

## Who
SA designs. PM breaks down tasks.

## How
1. Grill the decisions that are expensive to change later (schema, data units, append-only records) per [`process/grilling.md`](../grilling.md), before designing.
2. SA writes `SA/SA_design.md` for the tech stack in the requirement: DB schema, API list, screen list.
3. PM breaks down tasks into `SA/tasks.md` — skill `to-tickets` (the human types `/to-tickets`):
   - One task per API endpoint, per screen, or per DB migration.
   - Each task references the SA section it comes from and names the target file path.
   - **Each task carries what Dev needs to finish it**: the acceptance criteria that apply, the constraints from the SA document, and the accepted risks that apply. Dev completes a task by opening only the SA sections the task cites.

## Output
`SA/SA_design.md`, `SA/tasks.md`

## Done when
Every requirement item maps to at least one DB table, API, or screen · every task has a reference and a path.

## Human approves
`SA/SA_design.md` and `SA/tasks.md` at their stated versions.
