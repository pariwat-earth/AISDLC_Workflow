# Stage 2 — Business analysis

## Who
BA.

## How
1. Read `BA/requirement.md` in full.
2. Grill the human per [`process/grilling.md`](../grilling.md) until every question has an answer.
3. Write `BA/BA_analysis.md`: the main job of each user role, the business rules, and the acceptance criteria.
4. **Acceptance criteria** (full level): one per requirement item, in the form **"When <event>, the system must <observable result>"** — for example "When a clerk cancels a paid bill, the system must ask for the manager's code." One sentence is one QA case. An item that cannot be written in this form is still ambiguous: grill it.
5. Decisions that override the requirement go back into `BA/requirement.md` (CLAUDE.md section 4.1). Limitations the human accepts go into the accepted-risk table (section 4.2).

## Output
`BA/BA_analysis.md`

## Done when
Every grilling question has an answer · `BA/BA_analysis.md` states the main job of each user role · every requirement item has acceptance criteria.

## Human approves
`BA/BA_analysis.md` at its stated version: the main jobs, the rules, and the acceptance criteria.
